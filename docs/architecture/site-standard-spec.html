LEVERAGEAI · Package Specification · @leverageai/site-standard v1.0.0

One Package, Two Properties, Zero Drift.

Author: Claude — Technical SEO Architect Date: 2026-07-13 Runtime deps: 0 TypeScript: strict + exactOptionalPropertyTypes — PASS Guard tests: 6/6 PASS

@leverageai/site-standard is the shared Astro layer that closes every cross-cutting audit finding on both properties in one maintained place: a validated SiteIdentity config, a canonical policy module (apex + trailing-slash-always — canonicals can never point at a redirecting variant again), a SchemaGraph component that ships a self-contained JSON-LD @graph on every page type from service pillars to directory business entities, a SeoHead component with full OG/Twitter cards, the Cloudflare Bulk Redirect CSV for both www hosts, and three post-build guards that fail CI on leaked drafting language, wrong canonicals, or missing schema. Zero runtime dependencies; strict TypeScript throughout; every guard tested against clean and violating fixture builds.

02Data Flow

One IDENTITY constant per repo, one PageMeta object per page. Everything else is derived — no page can hand-roll a canonical or a schema block.

// per repo, once:
src/site.ts        defineSiteIdentity({...})  → throws SiteStandardConfigError on www / http / trailing slash

// per page, in frontmatter:
const page: PageMeta = { type, title, description, path, breadcrumbs?, faqs?, … }

// in the base layout <head>:
<SeoHead     identity={IDENTITY} page={page} />   → canonicalFor() → apex + trailing slash, OG/Twitter
<SchemaGraph identity={IDENTITY} page={page} />   → buildGraph() → @graph, escaped, one script tag

// after astro build, in CI:
node scripts/lint-banned-phrases.mjs  dist   → exit 1 on drafting-language leak
node scripts/validate-canonicals.mjs  dist   → exit 1 unless canonical == SITE_URL+route+/
node scripts/validate-schema.mjs      dist   → exit 1 unless every page ships a valid graph
Design decision — self-contained graphs

Organization, Person (founder), and WebSite nodes ship on every page with stable @ids (/#organization, /#founder, /#website), and page-type nodes reference them. Costs a few hundred bytes per page; removes any dependency on crawlers stitching entities across URLs, and makes the schema guard's "Organization present" assertion meaningful on every page.

FAQPage discipline (invariant rule 4)

FAQPage renders only when the page's own faqs array is populated. The component cannot inherit FAQs from a parent template — the exact mechanism that produced the directory's R1 boilerplate finding is structurally unavailable.

04CI Guards

GuardFails the build whenCloses
lint-banned-phrasesRendered copy contains drafting language: "the reference pages", "schema package reference", "per the brief/spec", "the provided content", "as an AI", TODO/TKTK/lorem. Script/style stripped first so JSON-LD can't false-positive.N2 network
validate-canonicalsAny indexable page whose canonical isn't exactly SITE_URL + route + '/' — catches www hosts, slash-less variants, and missing tags. 404/500 excluded.N4 network · invariant guard #2 directory
validate-schemaAny indexable page with zero ld+json blocks, unparseable JSON, or no Organization node in the graph (proof the component actually rendered, not just any script tag).N1 network · R5 follow-through directory

All three are zero-dependency Node scripts run against dist/; ci/site-standard.yml wires them after astro check + tsc --noEmit + build, on Bun per house standard.

05Per-Repo Rollout

leverageai.network

1. Add dep; set trailingSlash: 'always', build.format: 'directory', site = apex.
2. Create src/site.ts IDENTITY (founder block included — powers Person/E-E-A-T nodes).
3. Replace hand-rolled head with <SeoHead/> + <SchemaGraph/> in the base layout; delete the homepage's inline graph (the component supersedes it).
4. Add PageMeta frontmatter per template: services → service (+ existing "Quick Answers" as faqs), locations → location, reports/blog/KB → article, portfolio → caseStudy.
5. Rewrite the two N2 paragraphs, then wire CI — the phrase guard keeps them dead.
6. Convert internal links to trailing-slash form (the canonical guard + a crawl will surface stragglers).

oregonsmbdirectory.com

1. Same dep + config alignment (already trailing-slash serving — lowest-friction adopter).
2. IDENTITY with directory branding; keep existing OG defaults as defaultOgImageUrl.
3. Swap templates onto the shared components: listing pages → listing with listItems from D1 (URLs = Tree A canonical homes, enforcing invariant Rule 1 in markup), business pages → business with rating/geo from D1.
4. Category FAQs stay on category pages only — business pages get entity-specific faqs or none (R1 fix rides this migration).
5. CI guards join the invariant's route/dedup guards in the same workflow.

Host redirects — one upload covers both audits' findings

Cloudflare dashboard → Account → Bulk Redirects → create list → import redirects/leverageai-host-redirects.csv → enable in a Bulk Redirect Rule. Two rows, official CSV format (no header): both www hosts 301 → apex with query preserved and path suffix carried. Closes N3 and the directory's R2 in one action.
